# [Salus v1.2.0 — Now in Production Maintenance](https://github.com/jabbott-iii/Salus/releases/tag/v1.2.0)

I am proud to announce that **Salus** has reached its production maintenance phase!

Salus is a Go CLI that checks a host's disk, memory, CPU, Docker, Kubernetes, services, clock, certificates, and common misconfigurations. It then prints a concise **PASS / WARN / FAIL** summary, with an exit code that reflects the worst result. With v1.2.0, the set of checks, the output formats, and the exit codes are settled. Every recorded security finding has a fix, and every release is built, signed, and published automatically. From here on, the focus shifts from building new features to keeping Salus stable, secure and up to date.

It has been five weeks since v1.0.0 shipped on September 27, with four releases since then (v1.0.1, v1.0.2, v1.1.0 and v1.2.0). Here is what came together to get here.

## What's new in v1.2.0

- **An importable package**
  - All of Salus's code moved from `internal` (a Go directory whose packages other modules cannot import) into an importable `pkg` package, and `main.go` now only holds the build version and the command wiring (the code that sets up the CLI's commands)
  - This lets [Capsus](https://github.com/jabbott-iii/Capsus), my toolbox that bundles every command-line tool I have built into one binary, run Salus as one of its commands

- **Cleaner container package page**
  - The container image's signed build provenance (a signed record of how and where the image was built) is now stored with GitHub, instead of being pushed to the registry as an extra `sha256-…` tag
  - Without that extra tag, the GitHub Packages page shows `latest` in its `docker pull` command
  - `gh attestation verify oci://ghcr.io/jabbott-iii/salus:1.2.0` still finds and checks the provenance

v1.2.0 doesn't change any check, flag, output format or exit code, so it is a drop-in upgrade from v1.1.0.

## Where Salus stands

- **12 checks**
  - System resources: `disk-space`, `disk-inodes` (inodes are the records a filesystem keeps for each file and directory), `memory`, and `cpu-load`, each with its own WARN and FAIL thresholds
  - Containers and clusters: `docker-status`, `kubernetes-status`, and `kubernetes-pods`, including unhealthy or restarting containers, node pressure (a cluster machine running low on memory, disk, or process IDs), and crash-looping pods (pods, Kubernetes's groups of containers, that keep crashing and being restarted)
  - Services and time: `service-uptime`, `systemd-failed` and `time-sync`
  - Certificates: `cert-expiry` for PEM (text) and DER (binary) files, with a configurable warning window (how long before expiry it starts to warn)
  - Configuration: `misconfig`, with a stable rule ID on every finding, such as `sshd-root-login`

- **Monitoring and continuous integration (CI) output**
  - `--format` selects `text`, `json`, `nagios`, `prometheus` or `junit`
  - Exit codes `0` to `3` follow the Nagios plugin convention (the exit codes Nagios expects from its plugins), so Salus works as a plugin for the Nagios, Icinga, or Zabbix monitoring systems without a wrapper script
  - Prometheus output is made for node_exporter's textfile collector, which reads metrics from files and exposes them to the Prometheus monitoring system
  - `--output` replaces the report file atomically, so a reader never sees a half-written report

- **Run history**
  - Every `check run` is saved to a local SQLite database
  - `salus jobs diff`, `salus jobs stats`, and `salus jobs prune` compare runs, spot flapping checks (ones whose result keeps switching from run to run), and keep the database small

- **Built for unattended runs**
  - `--check-timeout` and `--run-timeout` turn a hung check into a FAIL instead of a stuck run
  - Several Salus processes can share one database, and the report is written before the run is saved

- **Cross-platform**
  - Disk, inode, memory, CPU load and uptime checks measure the host on Linux, macOS and Windows

Every check and flag is covered in the [v1.1.0 release post](/intro/2026/10/05/salus-v1.1.0-release.html) and the [README](https://github.com/jabbott-iii/Salus#usage).

## Production hardening

- **Security**
  - 10 security findings recorded, each with a fix shipped
  - The findings include option injection (input that a program reads as a command-line option) through `--service` into `systemctl`, a container that ran as root, a database created with default permissions, unsigned releases, and external tool output that reached the terminal and the database unfiltered
  - External commands are bounded by the timeouts, their output is capped, and on Linux and macOS, Salus stops the processes it started when an external command times out
  - The CodeQL, gosec, and govulncheck security scanners run on every change and weekly

- **Testing**
  - CI runs `go vet`, golangci-lint and the full test suite on Linux, macOS and Windows, then smoke-tests the built binary (runs it briefly to confirm that it works)

- **Release & Supply Chain**
  - Native binaries for Linux, macOS and Windows on x86-64 and ARM64
  - Linux binaries are statically linked, so they do not depend on the system's C library
  - Every release file and the container image carry `checksums.txt` and a signed SLSA (Supply-chain Levels for Software Artifacts) build provenance attestation
  - The multi-architecture image (`linux/amd64`, `linux/arm64`) at `ghcr.io/jabbott-iii/salus` runs as an unprivileged (non-root) user with user ID (UID) `10001`
  - Third-party GitHub Actions are pinned by commit SHA (the hash that identifies one exact commit) and base images by digest (a hash of the image's contents), and Dependabot (GitHub's automated dependency updater) keeps them current

## Upgrading

From v1.1.0, replace the binary or pull the new image; nothing else changes.

From v1.0.2 or older, read the README's [Upgrading from 1.0.2](https://github.com/jabbott-iii/Salus#upgrading-from-102) first. A plain `salus check run` now runs more checks, `docker-status` and `kubernetes-status` are stricter, and `misconfig` messages start with a rule ID. As a result, some hosts that passed before now report WARN. Choose checks with `--only`, or pass `--fail-on fail` to let WARN pass.

To verify a download before you run it:

```bash
gh attestation verify salus_linux_amd64.tar.gz --repo jabbott-iii/Salus \
  --signer-workflow jabbott-iii/Salus/.github/workflows/cd.yml \
  --source-ref refs/tags/v1.2.0
```

## Roadmap

Salus is now in production maintenance. Going forward:

- Bug fixes and security patches ship in the next release; only the latest release is supported
- Dependencies and the Go toolchain are kept current
- Stability comes first; new features are not the focus

Found a vulnerability? Please report it privately through the repository's [Security tab](https://github.com/jabbott-iii/Salus/security/advisories/new), as described in [SECURITY.md](https://github.com/jabbott-iii/Salus/blob/main/SECURITY.md).

Thank you for following along!
